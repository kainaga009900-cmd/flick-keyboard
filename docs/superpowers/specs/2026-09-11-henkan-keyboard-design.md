# 押し間違えないフリックキーボード 設計書

- 作成日: 2026-09-11
- アプリ名: **未定**（仮称「変換キーボード」。名前は後で決める）
- 対象: iPhone（第1〜3版）→ Android（別の設計書で）

## 1. 目的

スマホで**予測変換の候補を押し間違える**のを防ぐ、日本語フリック入力キーボードを作り、App Store でみんなに配る。

押し間違いの原因は次の2つだと考える。

1. 打った読みと違う言葉（打ち間違いの自動補正や、関係ない予測）が候補に混ざり、それを押してしまう。
2. 一度間違えて選んだ言葉をスマホが覚えて、次から上に出てくる。

このキーボードは、この2つを起こさないことを一番の特徴にする。

## 2. 画面

今使っているキーボード（Simeji）と同じ並びにする。AIの部分（返信提案・話題提案・ムード分析・豆知識・ロボットのアイコン）、🔍検索、道具の段のマイク、💬ボタンは入れない。

```
打っていない時                       打っている時
┌──────────────────────────┐        ┌──────────────────────────┐
│ [⚙] [カーソル] [顔文字] [閉じる]│ ←道具の段 │ 会議 懐疑 回議 カイギ    │ ←変換の段（太い）
│                          │        │ 会議室 会議中 会議の      │ ←予測の段（細い）
├────┬────┬────┬────┬────┤        ├────┬────┬────┬────┬────┤
│記号│ あ │ か │ さ │ ⌫ │        │記号│ あ │ か │ さ │ ⌫ │
│123 │ た │ な │ は │空白│        │123 │ た │ な │ は │次候補│
│あA │ ま │ や │ ら │改行│        │あA │ ま │ や │ ら │確定│
│ ☺ │ ^^ │ わ │、。?!│    │        │ ☺ │小゛゜│ わ │、。?!│    │
└────┴────┴────┴────┴────┘        └────┴────┴────┴────┴────┘
```

- 道具の段と候補の段は**同じ場所・同じ高さ**。打ち始めると道具の段が「変換の段＋予測の段」に入れ替わる。
- **キーボード全体の高さは常に同じ**。予測がないときは予測の段を空欄で残す（高さが変わって画面がガタつくと、それ自体が押し間違いの原因になるため）。
- 画面の一番下にある 🌐 とマイクは iPhone 本体のもので、そのまま使える。ホームボタンがある iPhone（🌐 が出ない機種）では、左下の ☺ の位置に 🌐 を出す。
- LINE の「＞（写真・カメラ）」と「スタンプ」は LINE アプリ側のボタンなので、このキーボードでもそのまま使える（作らない）。

## 3. 候補の出し方（このアプリの核）

### 3.1 変換の段（太い段）

- 打った読みと**完全に一致する**変換候補だけを出す。
  - 例：「かいぎ」→ 会議 / 懐疑 / 回議 / カイギ / かいぎ
- 長い文を打っているときは、頭から区切った部分の候補（例：「あしたかいぎ」の「明日」）も出してよい。これも読みは打った文字と一致している。
- **打ち間違いの自動補正はしない**。読みが違う言葉は一切出さない。

### 3.2 予測の段（細い段）

- 打った読み**で始まる**言葉だけを出す（例：会議室 / 会議中 / 会議の）。
- 文字を小さく、段を細くして、変換の段と見た目で区別する。
- 予測は変換の段に混ぜない。

### 3.3 エンジンの設定

変換エンジンは azooKey の [AzooKeyKanaKanjiConverter](https://github.com/azooKey/AzooKeyKanaKanjiConverter)（MIT ライセンス）を使う。`ConvertRequestOptions` は次のようにする。

| 設定 | 値 | 理由 |
|---|---|---|
| `typoCorrectionMode` | `.disabled` | 打ち間違いの自動補正を出さない |
| `requireJapanesePrediction` | `.manualMix` | 予測を変換候補と分けて受け取り、予測の段にだけ出す |
| `requireEnglishPrediction` | `.disabled` | 日本語フリックでは不要 |
| `learningType` | `.nothing` | エンジンには覚えさせない（覚え方は 4 章の自前ルールで管理） |
| `zenzaiMode` | `.off` | AI 変換モデルは使わない（容量とメモリを抑える） |

さらに念のため、エンジンが返した候補を自前でもう一度ふるいにかける。

- 変換の段：読みが「打った読み全体」または「打った読みの頭から区切った部分」と一致しないものは捨てる。
- 予測の段：読みが打った読みで始まらないものは捨てる。

## 4. 覚え方のルール

「基本は覚えない。何度も使った言葉だけ覚える」。

1. 覚える単位は「読み」と「選んだ言葉」の組み合わせ（例：かいぎ → 会議）。
2. 確定するたびに回数を1足す。**3回**になったら、その読みを打ったときに変換の段の先頭に出す。
3. **確定してすぐ消したら数えない**。確定した言葉を5秒以内に ⌫ で消したら（そのあいだに文字を打ったり候補を選んだりしていなければ）「押し間違い」とみなし、その確定は回数に入れない。頭の部分だけ確定して、残りの読みを ⌫ で直すだけなら、確定した言葉は消していないので数える。
4. 3回に届いていない言葉は、候補の順番に一切影響しない（1回だけの間違いが上に来ることはない）。
5. 覚えておく数は最大5,000組。超えたら、一番長く使っていない組から消す。
6. キーボードの道具の段に ⚙ を置き、そこから「覚えた言葉を全部忘れる」を押せるようにする（押すと「本当に全部忘れますか？」と確認する）。フルアクセスなしのキーボードは設定アプリとデータを共有できないため、ボタンは設定アプリではなくキーボードの中に置く。
7. 覚えた内容は iPhone の中（キーボード自身の保存場所）にだけ保存し、外に送らない。

## 5. キーの動き

| キー | 打っていない時 | 打っている時 |
|---|---|---|
| あ〜わ | タップであ段、左い・上う・右え・下おのフリック（押している間は案内を表示） | 同じ |
| ^^ / 小゛゜ | 顔文字の一覧を開く | 直前の文字を 小→゛→゜ の順に切り替える |
| 、。?! | タップで「、」、フリックで 。?! | 同じ |
| ⌫ | 1文字消す（長押しで連続） | 読みを1文字消す |
| 空白 | 全角スペース | 次の候補へ移る |
| 改行 | 改行 | 選んでいる候補で確定 |
| 記号 | 記号の一覧に切り替える | ― |
| 123 | 数字のキーに切り替える | ― |
| あA | ひらがな ⇄ 英字（英字も12キーのフリック） | ― |
| ☺（左下） | 絵文字の一覧を開く | ― |
| 道具：⚙ | 「覚えた言葉を全部忘れる」の画面を開く（4章） | ― |
| 道具：カーソル | 道具の段が ← → になり、押すと1文字ずつ移動（長押しで連続）。もう一度押すと戻る | ― |
| 道具：顔文字 | 顔文字・絵文字の一覧を開く | ― |
| 道具：閉じる | キーボードを閉じる | ― |

英字のキー配列が今のキーボードと違った場合は、第1版のテストのときに直す。

## 6. しくみ

```
iPhoneアプリ（App Store で配るもの）
├─ 設定アプリ …… 使い方の説明／ライセンス表示
│                  （第2版から着せ替え、第3版から辞書の設定）
├─ キーボード本体 …… 画面とキーの動き
└─ 共通の部品（KeyboardCore）
     ├─ 候補のふるい分け（3章）
     ├─ 覚え方のルール（4章）
     └─ フリックの文字の割り当て（5章）
```

- 言語は Swift（画面は SwiftUI）。
- 候補のふるい分け・覚え方・フリックの割り当ては「共通の部品」にまとめる。画面と切り離しておき、自動テストだけで正しさを確かめられるようにする。
- キーボード本体は「覚えた言葉」を自分の保存場所に置く。設定アプリとは共有しない（フルアクセスなしでは共有できないため。App Group は使わない）。
- 第1版は**フルアクセスを求めない**（`RequestsOpenAccess = NO`）。ネットには一切つながない。
- 対応 iOS は 17 以上を目安にし、azooKey エンジンが対応している範囲に合わせて計画時に決める。

## 7. 作って試す流れ

作業するパソコンは Windows、Mac はない。そのため組み立てはクラウドで行う。

1. Windows でプログラムを書く。Xcode のプロジェクトファイルは手で書かず、設定ファイル（XcodeGen）からクラウド上で作る。
2. GitHub の**公開**リポジトリに置く。GitHub Actions の macOS 環境（公開リポジトリなら無料）で次を自動で行う。
   - 共通の部品の自動テスト（`swift test`）
   - アプリの組み立て
   - TestFlight へのアップロード（main に入ったときだけ）
3. iPhone の TestFlight アプリで受け取り、実際に打つ。スクショで感想をもらって直す。1回あたり30分〜1時間ほどかかる。

### 自動テストで確かめること

- 変換の段に、読みが違う候補（打ち間違い補正）が出ない。
- 予測は予測の段にだけ出て、打った読みで始まるものだけ。
- 3回選ぶと先頭に出る。2回では出ない。
- 確定して5秒以内に ⌫ した確定は数えない。5秒過ぎてからの ⌫ や、別の操作のあとの ⌫ は数える。
- 5,000組を超えると、一番長く使っていない組から消える。
- 「全部忘れる」で空になる。
- フリックの方向ごとに正しい文字が出る（あ〜わ、小゛゜、、。?!）。

### iPhone で確かめること（毎回の版で）

- LINE・メモ・Instagram で打てる。
- フルアクセスを許可していない状態で、すべて使える。
- 打っている時・打っていない時で、キーボードの高さが変わらない。
- 記号・123・英字・顔文字・絵文字・カーソル移動・閉じるが動く。

### 鍵（シークレット）の扱い

- App Store Connect の API キーなど、組み立てとアップロードに使う鍵は **GitHub Secrets にだけ**置く。リポジトリ・チャット・メモには書かない。
- アップロードは main へのプッシュでだけ動かし、他人の変更依頼（プルリクエスト）では鍵を使う処理を動かさない。

## 8. 配る

- App Store の審査に出す。キーボードの審査ルール（4.4.1）を満たすこと：
  - 文字入力ができる／次のキーボードへ切り替えられる／フルアクセスなしで動く／他のアプリを起動しない。
- プライバシーの申告は「データを収集しない」。
- 設定アプリに azooKey（MIT）と辞書データのライセンスを表示する。辞書データのライセンスは計画時に確認する。

## 9. 版の計画

| 版 | 入るもの |
|---|---|
| 第1版 | 打つ・変換（2段の候補、覚え方のルール）、記号、数字、英字、顔文字、絵文字、カーソル移動、閉じる、⚙（全部忘れる）、設定アプリ（使い方・ライセンス） |
| 第2版 | 着せ替え：背景を自分の写真に／キーと文字の色／キーの透け具合。設定アプリで作り、道具の段に着せ替えボタンを足す。**着せ替えは無料**（有料にしない） |
| 第3版 | 言葉の意味を調べる：道具の段に「意味」ボタンを足す。できるだけネットなしの辞書で作る（使える辞書は第3版の計画時に調べる） |
| その後 | Android 版（別の設計書で。Google への登録が必要） |

## 10. 入れないもの

- AI の機能（返信提案・話題提案・ムード分析・豆知識）
- キーボード内のネット検索、道具の段のマイク（Apple の決まりで自作キーボードはマイクを使えない。iPhone 本体のマイクは使える）
- 💬（定型文など Simeji 独自のボタン）
- ローマ字（QWERTY）入力、iPad 向けの画面調整

## 11. 決まっていないこと

- アプリ名。表示名は後から変えられるが、アプリの ID（Bundle ID）は一度登録すると変えられない。そのため ID は名前に左右されない中立なものを計画時に決める。
- 収益化の方法。第1版は完全無料で出し、使う人が増えてから決める。候補は「応援（投げ銭）」「専門用語パック」「買い切りの有料アプリ」。どれを選んでも、お金のやりとりは設定アプリの中だけで行う（キーボードの画面には広告も課金も入れられない：審査ルール 4.4）。

## 12. 気をつけること

- **試すまでに時間がかかる**：直すたびに30分〜1時間待つ。遅すぎる場合は Mac の購入を考える。
- **キーボードが使えるメモリは少ない**：iOS の決まりで、自作キーボードが使えるメモリは限られている。azooKey は実際にこの制限の中で動いている。AI 変換モデルは切っておく。
- **ご本人にやってもらう手続き**：Apple の開発者登録（年99ドル）、TestFlight アプリのインストール、App Store Connect の API キー作成と GitHub Secrets への登録。どれもお金やアカウントに関わるので、ご本人が操作する（手順は1ステップずつ案内する）。
